# Movie Recommendation System with PyTorch and FAISS

This project is a **personalized movie recommendation system** developed as a machine learning portfolio project. It learns user preferences from historical movie ratings and generates personalized Top-N recommendations.

The system combines:

- **Matrix Factorization** trained with Bayesian Personalized Ranking (BPR);
- **user and movie embeddings** for personalized ranking;
- **FAISS** for efficient maximum-inner-product search;
- **popularity-based recommendations** as a baseline;
- **Recall@K and NDCG@K** for evaluating recommendation quality.

The primary focus of the project is evaluating whether personalized recommendations outperform a non-personalized popularity baseline on held-out interactions.

The final BPR model outperforms the popularity baseline on both evaluation metrics. An additional experiment with genre-aware BPR was conducted, but the genre-aware model did not improve the final results.

## Architecture

The system follows a collaborative filtering pipeline:

1. Historical user–movie ratings are loaded and transformed into numerical user and movie indices.
2. Positive interactions are identified using a rating threshold of 4 or higher.
3. Training triples are generated by pairing positive interactions with randomly sampled negative items.
4. A Matrix Factorization model is trained using the BPR objective to rank positive interactions above negative ones.
5. The best training epoch is selected using validation Recall@10 and NDCG@10.
6. The final model is retrained on the complete training split.
7. Movie embeddings and movie biases are used to build a FAISS inner-product index.
8. For a given user, the system retrieves and ranks movies, excludes movies already rated in the training data, and returns the Top-N recommendations.

The FAISS index uses IndexFlatIP, an exact inner-product search index. Movie biases are incorporated into the indexed vectors so that the ranking matches the scoring function of the trained model.

## Data

The project uses MovieLens user–movie rating data.

Each interaction contains a user ID, movie ID, rating, and timestamp. The original identifiers are mapped to contiguous integer indices for model training.

### Dataset Statistics

| Property                                    | Value      |
|---------------------------------------------|------------|
| Total rating interactions                   | 100,836    |
| Training interactions                       | 80,419     |
| Test interactions                           | 20,417     |
| Users represented in the training data      | 610        |
| Movies represented in the training catalog  | 8,230      |
| Known test interactions used for evaluation | 18,715     |
| Users evaluated on the test set             | 591        |
| Positive interaction threshold              | Rating ≥ 4 |

The test set contains interactions involving users or movies not represented in the training data. Evaluation is restricted to known user–movie pairs, and only test interactions rated 4 or higher are treated as relevant.

### Data Processing

The data preparation pipeline includes:

1. Loading the predefined training and test splits.
2. Mapping user and movie IDs to integer indices.
3. Creating a chronological validation split from the training data.
4. Identifying positive interactions using the rating threshold.
5. Sampling negative movies that a user has not positively rated in the relevant training subset.

The existing train/test split is kept fixed to make the reported evaluation reproducible.

Before installing the project, make sure the following software is available:

- Git
- Python
- pip

```bash
cd movie-recommender-pytorch
```

### 2. Create and activate a virtual environment

**Windows**

```cmd

.\.venv\Scripts\Activate.ps1
```

**Linux / macOS**

```bash
python -m venv .venv
source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

## Usage

Run commands from the repository root.

### 1. Train the model

```bash
python -m src.train
```

The training pipeline:

- trains the BPR Matrix Factorization model;
- evaluates ranking quality on the validation split;
- applies early stopping based on validation NDCG@10;
- retrains the final model on the complete training split;
- saves the model checkpoint and training metadata.

Expected outputs include:

- models/bpr_model.pt
- models/bpr_metadata.json
- reports/bpr_training_history.csv

### 2. Evaluate the model

```bash
python -m src.evaluate
```

This command compares the BPR model with the popularity baseline on the held-out test set.

The results are saved to:

```text
reports/test_metrics.csv
```

### 3. Build the FAISS index

After training the model, build the movie index:

```bash
python -m src.build_index
```

The script extracts movie embeddings and biases from the trained model and saves:

- models/movie_index.faiss
- models/movie_index_ids.npy

The second file maps FAISS index positions back to the original MovieLens movie IDs.

### 4. Generate recommendations

Generate the Top-10 recommendations for a user:

```bash
python -m src.recommend --user-id 1 --top-k 10
```

To request the Top-20 recommendations:

```bash
python -m src.recommend --user-id 1 --top-k 20
```

The script prints the ranked movie IDs and titles. Movies already rated by the user in the training data are excluded from the recommendation list.

Only users represented in the training data are supported by the current model.

### 5. Verify the FAISS index

```bash
python -m src.check_index
```

The verification script compares the Top-10 movie rankings produced by FAISS with rankings computed directly by the trained model.

For the tested user, the two methods returned the same movies in the same order.

## Experiments

The project includes experiments with different collaborative filtering approaches.

### BPR Matrix Factorization

The primary model represents users and movies as trainable embedding vectors. It is trained with the Bayesian Personalized Ranking objective, which encourages positive interactions to receive higher scores than sampled negative interactions.

The model also includes user and movie bias terms.

### Genre-aware BPR

An additional experiment investigated incorporating movie genre information into BPR recommendations.

The genre-aware model did not outperform the standard BPR model in the final test evaluation. Therefore, the standard BPR model was selected as the primary model.

The experiment and its training and sweep histories are available in notebooks/02_bpr_with_genres.ipynb and the corresponding CSV files in reports/.

## Evaluation

Recommendation quality is evaluated using Recall@10 and NDCG@10.

- **Recall@10** measures the fraction of relevant test movies retrieved in the Top-10 recommendations.
- **NDCG@10** measures ranking quality, assigning greater importance to relevant movies placed closer to the top of the list.

The BPR model is compared with a popularity baseline that ranks movies by the number of training interactions. Both methods are evaluated on the same set of 591 users with at least one relevant test interaction.

### Test Results

| Model                          | Recall@10 | NDCG@10 |
|--------------------------------|-----------|---------|
| Popularity baseline            | 0.05013   | 0.07595 |
| **Matrix Factorization (BPR)** | 0.05219   | 0.08331 |
| Relative improvement           | +4.1%     | +9.7%   |

The BPR model outperforms the popularity baseline on both metrics:

- Recall@10 improves by approximately 4.1%.
- NDCG@10 improves by approximately 9.7%.

The results demonstrate that personalized collaborative filtering can improve recommendation ranking over a simple popularity-based approach on this dataset. The observed improvements are not, by themselves, evidence of statistical significance.

The final metrics are stored in reports/test_metrics.csv.

## Limitations

- **Cold-start problem**: the model cannot generate personalized recommendations for users absent from the training data or rank movies absent from the training catalog.
- **Limited dataset**: results are based on a relatively small dataset and may not generalize to larger or more diverse recommendation settings.
- **Implicit ranking objective**: ratings of 4 or higher are treated as positive interactions, while negative samples are generated from movies not positively rated in the training subset. Unrated movies are not necessarily disliked.
- **Moderate improvement**: BPR outperforms the popularity baseline, but the absolute improvement in Recall@10 is relatively small.
- **Exact FAISS search**: IndexFlatIP performs exact search over the indexed catalog. It provides a straightforward retrieval implementation, but it does not demonstrate the speed–accuracy trade-off of approximate indexing at large scale.
